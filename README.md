# LIT Cinema 🍿

Наш маленький кінотеатр уже вміє рахувати ціни та показувати вільні місця. Твоє завдання — написати тести й перевірити його роботу.

Працюватимемо зі звичайними методами, `RSpec.describe`, `it` та `expect`. Дані для кожного тесту записуватимемо просто всередині `it`.

## 1. Запусти застосунок

Відкрий папку `lit_cinema` у VS Code та відкрий у ній термінал. У цій папці є `app.rb` і папка `lib`.

```bash
ruby app.rb
```

Програма покаже готовий приклад покупки. Вік, кількість квитків і зайняті місця можна змінювати в `app.rb`.

Методи для тестування лежать у `lib/cinema.rb`. Під час написання тестів підключай цей файл.

## 2. Правила кінотеатру

| Метод | Що він повертає |
| --- | --- |
| `cinema_name` | Рядок `'LIT Cinema'` |
| `ticket_price(age)` | 80 грн для віку 0–11, 100 грн для 12–17, 150 грн від 18 років |
| `total_price(age, count)` | Суму за `count` квитків за тарифом для `age` |
| `allowed_to_watch?(age)` | `true`, якщо вік від 12 років; інакше `false` |
| `snacks` | Масив `['попкорн', 'сік', 'начос']` у такому порядку |
| `snack_price(name)` | Ціну снека: попкорн — 60, сік — 40, начос — 70; для іншої назви — `nil` |
| `free_seats(booked_seats)` | Масив вільних місць з номерів 1–5, від меншого до більшого |

`ticket_price` — загальний тариф кінотеатру, а `allowed_to_watch?` — перевірка доступу до конкретного фільму 12+. Тому дитячий тариф існує, навіть якщо цей фільм дитині ще не можна дивитися. `total_price` лише рахує суму за тарифом.

Для цього заняття передаємо коректні дані: вік і кількість квитків — цілі числа від нуля; назва снека — рядок малими літерами; зайняті місця — масив різних цілих чисел від 1 до 5. Для нуля квитків сума дорівнює нулю. Порожній масив зайнятих місць означає, що всі місця вільні.

Усі ціни — у гривнях. Додавати обробку неправильних даних у цій вправі не потрібно.

## 3. Встанови RSpec

Ruby та Bundler мають бути встановлені. Перевір:

```bash
ruby -v
bundle -v
```

Якщо Ruby працює, але команда `bundle` не знайдена, встанови Bundler для своєї Ruby:

```bash
gem install bundler
```

З папки `lit_cinema` виконай:

```bash
bundle init
bundle add rspec --version '~> 3.13'
bundle exec rspec --init
```

- `bundle init` створює `Gemfile`.
- `bundle add` додає RSpec до `Gemfile` та встановлює його.
- `rspec --init` створює `.rspec` і `spec/spec_helper.rb`.

Ці команди потрібні один раз під час підготовки проєкту. Для наступних запусків тестів достатньо `bundle exec rspec`.

## 4. Увімкни формат documentation

Відкрий згенерований файл `.rspec` у корені `lit_cinema` та зроби його вміст таким:

```text
--require spec_helper
--format documentation
--color
```

Тепер RSpec показуватиме назви тестів, а не лише крапки. `spec_helper.rb` на цьому занятті можна залишити як є.

Формат можна також вказати для одного запуску:

```bash
bundle exec rspec --format documentation
```

## 5. Напиши перший тест

Створи файл `spec/cinema_spec.rb` і встав:

```ruby
require_relative '../lib/cinema'

RSpec.describe 'Кінотеатр' do
  it 'повертає назву кінотеатру' do
    result = cinema_name

    expect(result).to eq('LIT Cinema')
  end
end
```

Запусти:

```bash
bundle exec rspec
```

Наприкінці має бути:

```text
1 example, 0 failures
```

Що тут відбувається:

- `require_relative` підключає файл з методами.
- `RSpec.describe` об'єднує пов'язані тести.
- `it` описує одну перевірку.
- `result = cinema_name` викликає справжній метод застосунку.
- `expect(result).to eq('LIT Cinema')` перевіряє очікуваний результат.

**Нові блоки `it ... end` додавай усередині `RSpec.describe`, перед його останнім `end`.** У кожного тесту мають бути власні дані та виклик методу.

## 6. Подивися на помилку

У першому тесті тимчасово заміни очікувану назву `'LIT Cinema'` на `'Super Cinema'`. Запусти тести ще раз.

Знайди в повідомленні `expected` — очікуване значення, та `got` — отримане. Після цього поверни правильну назву й знову отримай `0 failures`.

Коли тест не проходить, порівнюй результат із правилами кінотеатру. Помилка може бути як у застосунку, так і в самому тесті.

## 7. Базові завдання

Для кожного рядка створи окремий `it`. Перше завдання вже зроблено вище. Почни із завдань 2–7, потім переходь до масивів і снеків.

| № | Що перевірити | Очікування | Підказка |
| --- | --- | --- | --- |
| 1 | Назва кінотеатру | `'LIT Cinema'` | `eq` |
| 2 | Квиток для 10-річної дитини | `80` | `eq` |
| 3 | Квиток для 14-річного підлітка | `100` | `eq` |
| 4 | Квиток для 20-річного дорослого | `150` | `eq` |
| 5 | Три квитки за тарифом для віку 10 років | `240` | `eq` |
| 6 | Доступ до фільму у 12 років | `true` | `be(true)` |
| 7 | Доступ до фільму в 11 років | `false` | `be(false)` |
| 8 | Попкорн є у списку снеків | Елемент присутній | `include` |
| 9 | Піци немає у списку снеків | Елемент відсутній | `not_to include` |
| 10 | Ціна соку | `40` | `eq` |
| 11 | Ціна невідомого снека `'піца'` | `nil` | `be_nil` |
| 12 | Вільні місця, коли зайняті `[2, 4]` | `[1, 3, 5]` | `eq` |
| 13 | Вільні місця, коли зайняті `[1, 2, 3, 4, 5]` | Порожній масив | `be_empty` |
| 14 | Вільні місця, коли зайнятих немає: `[]` | `[1, 2, 3, 4, 5]` | `eq` |

Після кожного нового тесту запускай `bundle exec rspec`.

## 9. Шпаргалка з expect

Це приклади синтаксису на простих значеннях. У своїх тестах перевіряй результат виклику методу застосунку.

```ruby
expect(2 + 2).to eq(4)
expect('Привіт, світ!').to include('світ')
expect(['кіт', 'пес']).to include('кіт')
expect(['кіт', 'пес']).not_to include('слон')
expect(true).to be(true)
expect(false).to be(false)
expect(nil).to be_nil
expect([]).to be_empty
expect(10).to be > 5
expect('Привіт').to start_with('При')
expect(['кіт']).to be_an(Array)
```

`eq` перевіряє весь результат; для масивів — також порядок елементів. `include` перевіряє лише наявність елемента або частини рядка.

Для методу, який обіцяє повернути саме `true` або `false`, використовуй `be(true)` чи `be(false)`. `be_truthy` перевіряє ширшу умову: у Ruby навіть `0` і порожній рядок є truthy.

Порівняння `be > 100` корисне для тренування, але не замінює перевірку конкретної ціни через `eq(150)`.

## 10. Корисні команди

```bash
# Усі твої тести
bundle exec rspec

# Один файл
bundle exec rspec spec/cinema_spec.rb

# Тести, у назві яких є слово «назву»
bundle exec rspec --example 'назву'
```

Якщо бачиш `No examples found`, перевір, що файл лежить у папці `spec`, його назва закінчується на `_spec.rb`, а всередині є `it` з блоком. Команди запускай із папки `lit_cinema`.
